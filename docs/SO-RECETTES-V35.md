## Essais de panne et concurrence à consigner pour chaque nouvelle tranche

- Double clic avec même commande ; autre requestId pour la même approbation/naissance ; réception perdue après commit ; coupure avant commit ; réouverture sur second appareil.
- Deux dernières places, réduction de quota sous effectif confirmé, retrait et approbation concurrents ; même identité fictive sur deux comptes.
- Deux MJ affectent une réserve à des participants différents ; deux remplaçants pour le même participant ; sélection d’un personnage déjà joué/mort.
- Mort/relève pendant action réservée ; XP acquis 0/3/6/35/36/100, hérités exclus ; deux décès dans la même session ; PA disponibles/réservés et calendrier commun inchangés.
- Révocation et paiement/stock/secret/pilotage ; effet commis avant révocation conservé, après révocation refusé ; retour réseau ne restitue pas un ancien mandat.
- Reprise d’une session archivée et de campagne sans nouveau kit, crédit, XP ou nouvelle autorisation ; aucun republish pour naissance/changement de groupe autorisé.

Chaque résultat final doit mentionner SHA, environnement, rôle, données fictives, appareil/navigateur si pertinent, commande/étapes, attendu, constaté, preuve et anomalie. Les limites d’appareils ou d’environnement doivent rester explicites.
